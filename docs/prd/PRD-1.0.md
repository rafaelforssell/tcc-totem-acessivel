# PRD — Totem de Autoatendimento com Recursos de Acessibilidade

## 1. Visão do Produto
O projeto consiste em um totem de autoatendimento acessível, desenvolvido para auxiliar usuários na busca, identificação e localização de produtos em lojas físicas, com foco especial em acessibilidade para pessoas com deficiência visual.

O sistema busca combinar interação por voz, processamento inteligente das consultas e retorno acessível em áudio e interface visual.

## 2. Problema
Em lojas físicas, a localização de produtos ainda depende, em muitos casos, da ajuda de atendentes ou da identificação visual do ambiente. Isso reduz a autonomia do cliente e cria barreiras importantes para pessoas com deficiência visual.

Além disso, a falta de recursos acessíveis pode tornar a experiência de compra mais lenta, frustrante e menos inclusiva.

## 3. Objetivo do Produto
Desenvolver um sistema de autoatendimento acessível que permita ao usuário consultar produtos por meio de interação simples, recebendo como resposta informações claras sobre o item solicitado e sua localização dentro do ambiente.

## 4. Público-Alvo
- Pessoas com deficiência visual
- Clientes em geral em ambientes varejistas
- Estabelecimentos que buscam melhorar acessibilidade e atendimento

## 5. Proposta de Valor
O produto busca oferecer:
- maior autonomia ao usuário
- melhoria da acessibilidade no varejo
- redução da dependência de atendimento humano para consultas simples
- experiência de compra mais eficiente e inclusiva

## 6. Escopo do MVP
A primeira versão do produto deve contemplar:
- captura da interação do usuário
- interpretação da consulta
- busca de informações de produto em base local
- retorno da resposta em formato visual
- retorno da resposta em formato sonoro
- funcionamento local

## 7. Funcionalidades Principais
- Receber consulta do usuário
- Processar a entrada recebida
- Identificar o produto solicitado
- Consultar a base de dados de produtos
- Retornar a localização do produto
- Sugerir alternativas quando necessário
- Exibir resposta em tela
- Reproduzir resposta em áudio

## 8. Requisitos Funcionais
- O sistema deve permitir consultas relacionadas a produtos
- O sistema deve consultar uma base local de dados
- O sistema deve retornar informações relevantes sobre o item solicitado
- O sistema deve apresentar a resposta de forma acessível
- O sistema deve permitir evolução futura da solução

## 9. Requisitos Não Funcionais
- O sistema deve ser acessível
- O sistema deve possuir interface simples e clara
- O sistema deve operar localmente
- O sistema deve ter organização modular
- O sistema deve permitir manutenção e evolução

## 10. Fluxo Principal do Usuário
1. O usuário inicia a interação com o totem
2. O sistema recebe a solicitação
3. O sistema interpreta a consulta
4. O sistema busca as informações relevantes
5. O sistema organiza a resposta
6. O sistema retorna o resultado em tela e áudio

## 11. Arquitetura em Alto Nível
O produto será organizado em camadas principais:
- interface de interação
- processamento da consulta
- lógica principal do sistema
- armazenamento e consulta de dados
- camada de resposta ao usuário

## 12. Critérios de Sucesso
- O sistema consegue executar o fluxo principal sem falhas críticas
- O usuário recebe respostas compreensíveis
- O sistema consegue localizar produtos da base cadastrada
- A experiência de uso é simples e acessível
- A solução demonstra viabilidade como protótipo funcional

## 13. Limitações Atuais e Evolução Futura
A solução ainda está em desenvolvimento e pode passar por mudanças na definição das ferramentas específicas adotadas.

A evolução futura pode incluir:
- expansão da base de produtos
- refinamento da interface
- melhoria da interpretação das consultas
- maior robustez na acessibilidade
- ampliação das capacidades do sistema
